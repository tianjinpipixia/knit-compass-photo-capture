# KIMI・Gemini調査／Human Review SOP

更新日: 2026-08-03  
版: 1.0.0

## 1. 目的

調査品質をAIツールの操作方法や特定担当者の経験だけに依存させず、別の担当者が同じ根拠を追跡・再確認できる状態にします。

## 2. 基本ルール

1. KIMI・Gemini等の回答は**候補情報**であり、そのまま確定しない
2. 事実、推定、未確認事項を分離する
3. メーカー、加工会社、糸商、販売会社を混同しない
4. 商品・糸・会社・原料には共通IDを付ける
5. 確定情報には根拠と確認日を必ず残す
6. 公式情報が存在しない場合は、未確認のまま保持してよい
7. 原料メーカー不明の販売会社は、メーカーとして登録しない

## 3. 標準フロー

`調査依頼 → AI候補作成 → 根拠収集 → 事実／推定分離 → Human Review → 確定または差戻し`

### Step 1: 調査依頼

最低限、次を指定します。

- 対象名・URL・写真
- 知りたい項目
- 既に確認済みの情報
- 禁止する推測
- 類似品や他社品を探すか

### Step 2: AI候補作成

AI出力は以下の形式にします。

- 確認できた事実
- 有力候補
- 推定
- 矛盾
- 未確認事項
- 使用したURL・資料

### Step 3: 根拠収集

各根拠に `evidence_id` を発行し、次を保存します。

- URLまたはファイル参照
- ページ名・資料名
- 発行主体
- 確認日時
- 対象箇所
- 根拠が支持する項目

### Step 4: 事実と推定の分離

例:

- 「混率表示に4%氨纶」＝確認できた事実
- 「スパンデックスが芯糸」＝構造資料がなければ推定
- 「販売ページに会社名がある」＝販売会社候補
- 「その会社が紡績した」＝生産証拠がなければ未確認

### Step 5: Human Review

レビュー担当は次を確認します。

- URLが対象商品・対象糸と完全一致しているか
- 一次情報か、転載・販売情報か
- メーカーと販売会社を誤認していないか
- 混率、番手、構造の記載を混同していないか
- AIが根拠にない内容を補っていないか
- 類似品を同一品として扱っていないか
- 確認日が記録されているか

### Step 6: 判定

| review_status | 意味 |
|---|---|
| `approved` | 確定登録可能 |
| `approved_with_limits` | 一部だけ確定、残りは未確認 |
| `needs_more_evidence` | 根拠不足で再調査 |
| `rejected` | 対象違い、誤読、根拠不成立 |
| `conflicting` | 信頼できる情報源同士が矛盾 |

## 4. 情報源ランク

| ランク | 情報源 | 扱い |
|---|---|---|
| S | 原料・糸メーカー公式、正式技術資料、試験報告書、認証機関 | 確定の中心根拠 |
| A | ブランド公式商品ページ、展示会公式、企業登記・公式会社情報 | 対象一致を確認して確定可能 |
| B | 正規販売会社、業界プラットフォーム、公式SNS | 補助根拠。製造者断定には不十分な場合あり |
| C | EC転載、ブログ、SNS投稿、出所不明画像 | 候補発見用。単独では確定不可 |

ランクが高くても、対象品番・URL・資料版が一致しなければ確定しません。

## 5. 信頼度

- `high`: 一次情報が対象と完全一致し、矛盾なし
- `medium`: 複数の独立した根拠が一致するが一次情報不足
- `low`: 単一の販売情報、類似品、構造推定のみ

信頼度は確認状態とは別です。`high`でもHuman Review前は `candidate` です。

## 6. 糸商・販売会社の評価ルール

メーカーまたは原料供給元を説明できない糸商については、次の扱いにします。

- 組織役割: `seller`
- メーカー欄: `unconfirmed`
- 提案順位: 低下
- 表示回数: 抑制可能
- ただし、価格、在庫、色展開など販売情報は別途評価

誤ってメーカーとして昇格させないことを優先します。

## 7. 調査記録の必須項目

- `research_id`
- 対象ID
- 調査質問
- 使用AI
- 実行日時
- 確認できた事実
- 推定
- 未確認事項
- 根拠一覧
- 情報源ランク
- 信頼度
- review_status
- reviewed_by
- reviewed_at

## 8. 品質KPI

月次で次を確認します。

- Human Review前後の修正率
- メーカー／販売会社の誤分類件数
- URL対象違い件数
- 根拠なし確定件数（目標0）
- 未確認を適切に残した件数
- 同一調査の再利用回数

修正率が高いAIプロンプトや情報源は、利用頻度・提案順位を下げます。
